## Authentication

Send a bearer token in the `Authorization` header:

```http
Authorization: Bearer <token>
```

A route's **Auth** line says what it needs:

| Auth | Meaning |
|---|---|
| Required | A valid token for an active user, or the route answers `401` |
| Optional | Works without a token; a token may widen what the caller sees |
| None | No token is read |

Two kinds of token are accepted wherever auth applies:

- **Hub access token**: a JWT from `POST /api/v1/auth/login`, valid for 30 minutes and renewed
  with `POST /api/v1/auth/refresh`.
- **Personal access token**: a long-lived token starting with `syft_pat_`, created with
  `POST /api/v1/auth/tokens`.

Some routes are further limited to admins or to the owner of the resource; their descriptions
say so. A **satellite token** is a different thing: a 60-second RS256 JWT the Hub mints with
`GET /api/v1/token` for a caller to present to another service (a Space, the aggregator). The
Hub's own routes do not accept it as a login.

## Errors

Errors are JSON with a `detail` member. It is a string for most errors and an object with a
`code` and `message` where a client needs to tell cases apart:

```json
{"detail": "Endpoint not found"}
```

```json
{"detail": {"code": "VALIDATION_ERROR", "message": "..."}}
```

Every route that takes input can also answer `422` with a
[`HTTPValidationError`](#httpvalidationerror) when the input does not match the schema. The
response tables below leave that row out.

### `POST /api/v1/auth/login`

### `POST /api/v1/auth/google`

Authenticate (and, by default, register) a user via Google OAuth.

Given the Google ID token (JWT) from Google Sign-In on the frontend:
- Existing user (matched by Google ID) → logged in.
- Email already on an account not linked to Google → 409 (never
  auto-linked; the user must link Google from account settings).
- Unknown email → a new account is created, UNLESS the request sets
  `allow_signup: false`, in which case it is rejected with 401
  (`code: account_not_found`) — for relying services that admit
  existing users only.

**Auth:** None. Rate limited.

**Request body:** [`GoogleAuthRequest`](#googleauthrequest) as `application/json`.

| Status | Meaning | Body |
|---|---|---|
| `200` | Successful Response | [`AuthResponse`](#authresponse) |
| `401` | Invalid Google token | e.g. `{"detail": "Invalid Google token"}` |
| `503` | Google OAuth not configured | e.g. `{"detail": "Google OAuth is not configured"}` |

### `GET /api/v1/endpoints/public/grouped`

List public endpoints grouped by their owner.

**No Authentication Required** - This endpoint is public.

**Purpose:**
This endpoint is designed for the Global Directory display, where showing
endpoints grouped by owner provides a better representation of the network's
diversity. It prevents a single owner with many endpoints from dominating
the entire listing.

**Response Format:**
Returns a list of groups, where each group contains:
- `owner_username`: The username of the endpoint owner
- `endpoints`: List of endpoints belonging to this owner (limited to `max_per_owner`)
- `total_count`: Total number of endpoints this owner has (may be more than shown)
- `has_more`: True if the owner has more endpoints than displayed

**Ordering:**
- Groups are ordered by total endpoint count (descending)
- Within each group, endpoints are ordered by `updated_at` (most recent first)

**Auth:** Optional.

### `POST /api/v1/endpoints/sync`

Synchronize user's endpoints with the provided list.

The list is everything the reporting satellite serves. The Hub diffs it
against what it has for that satellite, by slug:
1. Endpoints already known are updated in place and keep their id, stars,
   uptime history and collective membership
2. Endpoints not seen before are created
3. Endpoints the satellite no longer reports are deleted, along with their
   history
4. The whole diff is ATOMIC: either it all applies, or none of it does

**Important Notes:**
- Other satellites owned by the same account are not touched
- Maximum 100 endpoints per sync request

**Validation:**
- All endpoints are validated BEFORE any database changes
- If ANY endpoint fails validation, the entire batch is rejected
- All validation errors are returned together (not just the first)

**Empty Payload:**
- Sending an empty list `{"endpoints": []}` deletes the endpoints served by
  the resolved satellite

**Auth:** Required.

**Request body:** [`SyncEndpointsRequest`](#syncendpointsrequest) as `application/json`.

| Status | Meaning | Body |
|---|---|---|
| `200` | Sync completed successfully | [`SyncEndpointsResponse`](#syncendpointsresponse) |
| `400` | Validation error - batch contains invalid endpoints | e.g. `{"detail": {"code": "VALIDATION_ERROR", "message": "Batch validation failed with 2 error(s)", "errors": [{"index": 0, "field": "slug", "error": "'api' is a reserved slug"}, {"index": 2, "field": "slug", "error": "Duplicate slug 'my-model' in batch"}]}}` |
| `500` | Internal server error - sync failed | e.g. `{"detail": {"code": "SYNC_FAILED", "message": "Failed to sync endpoints. Transaction rolled back."}}` |

## Identity provider

### `GET /api/v1/token`

Mint a new, short-lived JWT specifically for a target service (Audience).
The returned token is signed by the Hub's Private Key using RS256.

**Token Claims:**
- `sub`: User's unique ID
- `iss`: Issuer URL (Hub URL)
- `aud`: The id of the satellite the token is for
- `exp`: Expiration timestamp (short-lived, typically 60 seconds)
- `role`: User's role (admin, user, etc.)

**Naming the destination:**
- Send `owner_username` and `resource`: the account that runs the service and
  the URL the token is about to be sent to
- The Hub resolves that pair to one of the owner's registered satellites and
  binds the token to it; an account that runs no satellite at that URL gets 422
- `aud` (a username) is deprecated and works only while the account runs
  exactly one satellite
- With none of them the route answers 400 (`MISSING_AUDIENCE`)

**Security:**
- Requires valid Hub session token
- A token minted for one satellite is not accepted at another
- Token cannot be refreshed - request a new one when expired

**Auth:** Required.

| Parameter | In | Type | Required | Default | Description |
|---|---|---|---|---|---|
| `owner_username` | query | string or null | no |  | Username of the account that runs the resource |
| `resource` | query | string or null | no |  | URL this token will be sent to. Must be a host the owner has registered; RFC 8707 calls this the resource indicator. |
| `aud` | query | string or null | no |  | Deprecated. Username of the target account. Works only while that account runs exactly one satellite; send owner_username + resource. |

| Status | Meaning | Body |
|---|---|---|
| `200` | Token generated successfully | [`SatelliteTokenResponse`](#satellitetokenresponse) |
| `400` | Missing parameter or Invalid Audience requested | [`SatelliteTokenErrorResponse`](#satellitetokenerrorresponse) |
| `401` | Unauthorized (Invalid or Expired Hub Token) |  |
| `503` | Service Unavailable (Identity Provider not configured) |  |

**No Authentication Required** - This endpoint is public and allows

**Token Claims:**

### `POST /api/v1/verify`

Verify a satellite token and retrieve user context.

This endpoint allows satellite services to verify tokens server-side instead of
using JWKS for local verification. The calling service must authenticate with
their own Hub session token.

**Authorization:**
A caller can only verify tokens addressed to its own satellites. Send
`satellite_id` to require one satellite in particular; without it a token
for any of the caller's satellites is accepted.

**Verification Checks:**
1. Token signature (RS256 with Hub's private key)
2. Token expiry (exp claim)
3. Token audience is one of the caller's satellites
4. Token issuer matches Hub URL
5. Token subject user is active (not deactivated/deleted)

**Response:**
- `valid: true` with user context if verification succeeds
- `valid: false` with error details if verification fails

**Auth:** Required.

**Request body:** [`TokenVerifyRequest`](#tokenverifyrequest) as `application/json`.

| Status | Meaning | Body |

| `200` | Token verification result (success or failure) | [`TokenVerifySuccessResponse`](#tokenverifysuccessresponse) or [`TokenVerifyErrorResponse`](#tokenverifyerrorresponse) |
