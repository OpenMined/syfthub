SyftHub Python SDKReference for the v2 design · mock 0.0.2

Everything the SDK exposes, with a short example for each thing you can call. Start with the tour if you are new; use the sidebar to jump to a class.

Compose, then execute

A search or a chat first shows what it will cost and what is held back. Nothing is sent until you say so.

Payment is a state, not an error

Each source comes back as returned, skipped with a reason, or waiting on a payment, with the fix attached. Nothing raises.

Views, not copies

filter, only, drop, top and + change what you look at. The raw responses stay as the Spaces returned them.

This page is generated from the package by build_docs.py. The examples are the ones the story and advanced notebooks run.

Quick tour

The whole flow in one screen: shortlist, search, pay, read, chat.

import syfthub

hub = syfthub.connect("https://hub.example.com")
hub.login(username="alice", password="secret")

# Shortlist some sources
picked = (
    hub.browse().matching("trial adverse events").filter(type="data_source")
    + hub.browse().pick("dave/notes", "olga/trials-assistant")
)

# Compose a search. Nothing is sent yet: you see the cost per source and what is held
search = hub.search("What adverse events were reported in phase 3 trials?",
                    sources=picked)
search

# One wallet is short: buy a bundle and pay at topup.checkout_url
topup = search.top_up("dave/notes", bundle="starter")

# Send it. Every source comes back returned, skipped with a reason, or payment required
results = search.execute()
recent = results.filter(published_gte="2024-01-01")

# Talk to a model about the results. Same pre-flight: price per message, your balance.
chat = recent.chat("ivan/gpt-mini")
chat.context                                   # what the next message will carry
chat.send("Summarise the serious adverse events.")

# A second opinion joins from here on, briefed with the transcript so far
chat.add("bob/llama-3")
chat.send("Do you agree, and what would you add?")["bob/llama-3"].text
chat.remove("ivan/gpt-mini")

# Add fresh evidence mid-conversation
more = hub.search("infection-related SAEs", sources=["heidi/shared-corpus"]).execute()
chat.use(chat.view + more)

chat.spent
# -> {'USD': 0.10}

Verbs at a glance

The handful of verbs you will use most, and where they live.

VerbLives onWhat it does
browse / find / gethubList endpoints, search the Hub for them, or open one.
filterSelection, Search, Results, ChatNarrow by type, owner or tag, or by document metadata. On a Search, the filter is sent to Spaces that support it.
matching / pick / +SelectionFuzzy-match, pick by name, combine two lists.
search, then executehub, SearchCompose a search and review its pre-flight, then send what passes.
top_upSearch, Results, Chat, WalletBuy a credit bundle for a wallet that is short. You get an invoice with a checkout URL.
retry / approve / proceed / skipResultsAct on skipped rows: re-send them, pay MPP charges, accept going over budget, or drop them.
only / drop / top / +ResultsViews over what came back. The raw responses are never changed.
chat / ask / aggregateResultsStart a conversation about the results, ask once, or hand them to the Aggregator.
sendChatOne message to every model in the room. Returns a reply per model.
use / view / contextChatSee what the next message carries and change which passages it uses.
add / removeChatChange who answers from the next message on.
resetChatStart the thread over, keeping the passages.

Badges on this page: proposed needs something the Space or Hub API does not have today. experimental marks the MPP rail. mock only exists only in this mock.

Connect

Open a session and sign in.

syfthub.connect

functionconnect(url='https://hub.example.com', *, aggregator_url=None, interactive=False) → Hub

Open a session against a Hub.

Nothing is sent until you browse, search, or chat. Sign in afterwards with hub.login.

ParameterTypeWhat it is
urlstrThe Hub's base URL. Default 'https://hub.example.com'
aggregator_urlstr | NoneWhere the Aggregator lives, if you use results.aggregate. Defaults to {url}/aggregator/api/v1. Default None
interactiveboolIn a notebook, render anything that is waiting on a payment as a widget with buttons, so you can top up without typing code. Default False

Returns A Hub you browse, search, and chat from.

Example
import syfthub

hub = syfthub.connect("https://hub.example.com")

# In a notebook, render payment decisions as widgets with buttons
hub = syfthub.connect("https://hub.example.com", interactive=True)

Hub

Your session with a Hub.

Everything starts here: sign in with hub.login, find endpoints with browse or find, compose a search with search, open a chat with chat, and check your prepaid balances with wallets. The Hub only talks to the Hub API and to Spaces when you ask it to.

Example
hub = syfthub.connect("https://hub.example.com")
hub.login(username="alice", password="secret")
hub.browse()

ParameterTypeWhat it is

browse(type=None, *, owner=None, free=None, tag=None, matching=None) → Selection

List everything the Hub offers: data sources and models together.

Returns one table you can keep narrowing. type and owner are applied by the Hub; the other three are applied in this client, so they cost no extra round trips. The same narrowing is available afterwards on the returned Selection through .filter(...), .matching(text) and .pick(...).

ParameterTypeWhat it is
typestr | NoneKeep one kind of endpoint: "data_source" or "model". Default None
ownerstr | NoneKeep endpoints published by this username. Default None
freebool | NoneTrue keeps only free endpoints, False only paid ones. Default None
tagstr | NoneKeep endpoints carrying this tag. Default None
matchingstr | NoneFuzzy, typo-tolerant text match over name, owner, description, and tags. Default None

Returns A Selection of endpoints, ready to pass to hub.search(sources=...).

Example
# Everything, with a pricing column
hub.browse()

# Only free data sources
hub.browse(type="data_source", free=True)

# Fuzzy, typo-tolerant match on name, description and tags
hub.browse(matching="trial adverse events")

search(query, *, sources, limit=5, similarity_threshold=0.5, history=None) → Search

Compose a search over several sources. Nothing is sent yet.

Pre-flight runs immediately from Hub metadata and your wallet balances: it estimates the cost of each source, checks prepaid balances, access lists and the session budget, and tells you which sources will be sent and which are held, and why. Review it, top up what is short, then call .execute().

ParameterTypeWhat it is
querystrThe question to send to every source. required
sourcesIterableWhich endpoints to ask: a Selection, Endpoint objects, or owner/slug paths. required
limitintHow many passages to ask each source for. Default 5
similarity_thresholdfloatDrop passages scoring below this, from 0 to 1. Default 0.5
historylist[dict[str, str]] | NoneEarlier conversation turns to send along, in {"role": ..., "content": ...} form. Pass chat.history to let the Spaces see the thread. Default None

Returns A Search showing its pre-flight. Call .execute() to send it.

Example
search = hub.search(
    "What adverse events were reported in phase 3 trials?",
    sources=picked,
    limit=5,
)
# Shows the pre-flight table. Nothing has been sent.
search
chat(models, *, sources=None, via='direct', limit=5) → Chat

Open a chat with one model or several, without searching first.

With sources, every message searches those sources first and the passages become the model's context. Without them, you are simply talking to the models. Pre-flight runs on every model right away, so you see the price per message and your balance before sending anything.

ParameterTypeWhat it is
modelsOne model path, or a list of them, for example ["ivan/gpt-mini", "bob/llama-3"]. required
sourcesIterable | NoneEndpoints to search before each message. Default None
viastr"direct" asks the model's Space; "aggregator" routes through the Aggregator. Default 'direct'
limitintHow many passages each search asks for. Default 5

Returns A Chat. Nothing is sent until .send(prompt).

Example
# Search these two sources before every message, then ask the model
live = hub.chat("bob/llama-3", sources=["carol/papers", "erin/trials"])
live.filter(published_gte="2024-01-01").top(4)
live.send("How many deaths were reported?")

Methods

filter(**filters) → Search proposed

Only return passages whose metadata matches.

Write each condition as field=value for an exact match, or add a suffix: field_gte, field_gt, field_lte, field_lt to compare, or field_contains for a substring.

Where the filtering happens depends on the source. A Space that advertises the field as filterable gets the filter in the request: it filters before limit and bills only the passages it returns. Every other source is filtered here, after limit, so raise limit when you filter hard. The pre-flight table says which happens for each source. Server-side filtering is PROPOSED; no Space supports it today.

ParameterTypeWhat it is
**filtersAnyConditions such as published_gte="2024-01-01" or author="R. Chitrakoot".

Returns This search, narrowed. Chainable.

Example
# Date filters go to the Spaces that support them; the author filter is applied here
search.filter(published_gte="2024-06-01", author="R. Chitrakoot")

# The pre-flight table now has a filters column: "at the Space" or "here, after limit"
search

execute() → Results

Send the search to every source that passes pre-flight.

Pre-flight is checked once more, then the passing sources are called in parallel. Sources that are held become skipped rows with their reason and, where it applies, a top-up attached.

Returns The Results, one row per source.

Example

# -> (4, {'USD': 0.13})

Results

What a search returned: one row per source, plus views and follow-up actions.

Each row is a SourceResult that was returned, skipped with a reason, or is waiting on a payment. Payment problems are rows with an action attached, never exceptions. Views such as filter, only, drop and top reshape what you look at without touching the raw responses.

The states a source or a reply can end up in.

Outcome

What happened to one source, or one model, after sending.

success means it answered. skipped means it did not; reason says why. payment_required means an MPP Space asked for a payment first (experimental).

ValueMeaning
successThe source answered.
skippedThe source was not answered. reason says why.
payment_requiredAn MPP Space asked for a payment first. Approve it with results.approve().
Example
r = results["dave/notes"]
r.outcome is Outcome.SKIPPED and r.reason is SkipReason.NO_CREDITS
# -> True

SkipReason

Why a source was skipped.

Decided from the client's pre-flight or from the reason_code the Space put in its policy_metadata envelope, never from the HTTP status alone. Reasons marked retryable are the ones results.retry() can act on.

ValueMeaning
no_creditsThe prepaid wallet is short. A TopUp is attached. Retryable.
over_budgetSending would cross the session budget. Decided in this client. Retryable.
access_deniedThe Space's access policy does not include you.
rate_limitedThe Space asked you to slow down. Retryable.
no_pricing_tierThe Space has no price that applies to you.
unreachableNetwork error, or the Space is down. Retryable.
not_foundThe Space does not know this endpoint.
blockedThe Space refused with 403 and gave no reason code.
by_userYou skipped it with results.skip(path).
Example
[(r.endpoint.path, r.reason.value) for r in results.skipped]
# -> [('dave/notes', 'no_credits')]

Attributes

retryable : bool

True for the reasons results.retry() can act on: no credits, over budget, unreachable, rate limited.

Example
[r for r in results.skipped if r.reason.retryable]

Rail

How an endpoint gets paid.

Prepaid rails (stripe, xendit, cluster) hold credits you top up ahead of time; they are the default flow. mpp pays per request at query time and is experimental. free costs nothing.

ValueMeaning
freeNo payment policy; calls cost nothing.
stripePrepaid credits held by the Space, bought through Stripe.
xenditPrepaid credits held by the Space, bought through Xendit.
clusterPrepaid credits held by a managed wallet that several Spaces share.
mppPay per request at query time; the Space answers 402 first. Experimental.
Example
ep.pricing.rail
# -> <Rail.XENDIT: 'xendit'>

Attributes

prepaid : bool

True for the credit-based rails: stripe, xendit, and cluster.

Example
ep.pricing.rail.prepaid
# -> True

Errors

Raised only for mistakes in how the SDK is called. Payment problems are never exceptions.

SyftHubError

Base class for every error the SDK raises. Catch it to handle any SDK error in one place.

Example
try:
    hub.whoami()
except syfthub.SyftHubError as e:
    print(e)

NotLoggedIn

You called something that needs a signed-in user. Call hub.login(...) first.

Example
try:
    hub.whoami()
except syfthub.NotLoggedIn:
    hub.login(username="alice", password="secret")

BudgetExceeded

An action would spend more than the session budget allows.

Raised by results.approve() when paying the pending MPP charges would cross the cap you set with hub.set_budget. Raise the budget, or approve fewer sources.

AttributeWhat it holds
neededHow much the action would cost, in currency.
remainingHow much of the budget is left.
currencyThe budget's currency.
Example
try:
    results.approve()
except syfthub.BudgetExceeded as e:
    hub.set_budget(e.needed)
    results.approve()

RunNotReady

The action does not apply in the current state, and the message says what to do instead.

For example: topping up a source that is not short of credits, or sending a message in a chat with no model in it.

Example
try:
    chat.top_up(bundle="starter")          # two models are short: which one?
except syfthub.RunNotReady as e:
    print(e)                               # "several models are short: name one, ..."

NothingToRun

Nothing is left to send: every source is already answered, skipped by you, or not retryable.

Reserved for execute() and retry(). The mock does not raise it yet.

Example
try:
    results.retry()
except syfthub.NothingToRun:
    print("every source is done")
